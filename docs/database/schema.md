# Database schema

The schema lives in `packages/database/src` and is the single source of truth
for Drizzle and `drizzle-kit`. Every primary key is a UUID generated by
`gen_random_uuid()`; every table records `created_at` and `updated_at` as
`timestamptz` and a `version` integer for optimistic locking. `deleted_at`,
where present, is the soft-delete marker (null = active).

The initial SQL migration is produced by `pnpm --filter @aahaarloop/database
generate`; [demo data and commands](demo-data.md) explain how it is applied.
See [environment configuration](../development/environment.md) for connection
strings. Schema changes must be reviewed by both developers before
they are applied to any shared Neon branch.

## Integrity rules

- All quantity/capacity/attempt/impact values carry `CHECK (... >= 0)`.
- `donations.remaining_quantity <= donations.quantity`.
- `organization_members` is unique on `(organization_id, user_id)`.
- One active claim per `(donation_id, recipient_org_id)`; cancelled and expired
  claims are excluded by a partial unique index.
- `donation_allergens` and `favorites` are unique on their pair of foreign keys.
- Indexes cover donation status/deadline, organization, location, claim status,
  pickup windows, event time and notification reads.
- Foreign keys use `cascade` for owned children, `set null` for optional
  references and `restrict` where history must be preserved.
