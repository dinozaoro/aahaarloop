# APK release workflow

`.github/workflows/apk-release.yml` builds the Android preview APK with EAS and
publishes it as a GitHub Release. Build profiles and versioning are defined in
[EAS build and install](./eas-build.md); this page covers the release automation.

## Triggers

- **Tag push** matching `v*` (for example `v0.1.0`).
- **Manual dispatch** with a required `tag` input, for re-releasing without a
  new commit. The tag must start with `v`.

Both paths resolve a single release tag first; that tag names the APK and the
GitHub Release.

## Steps

1. Checkout, set up pnpm and Node (from `.nvmrc`) and install with
   `--frozen-lockfile`.
2. Authenticate EAS with `expo/expo-github-action@v8` using `EXPO_TOKEN`.
3. `eas build --platform android --profile preview --non-interactive --json`
   — no `--no-wait`, because the workflow needs the finished APK. The JSON
   result provides `artifacts.buildUrl`.
4. Download the APK with `curl -fL --retry 3`, compute its SHA-256 with
   `sha256sum` and verify it with `sha256sum -c`.
5. Generate `RELEASE_NOTES.md` and `INSTALL.md` with
   `scripts/release-notes.mjs` (testable pure functions).
6. Publish the GitHub Release with `softprops/action-gh-release@v2`, attaching
   the APK, its `.sha256` file and the install notes.

## Secrets and configuration

| Value                 | Source                                               | Purpose                                          |
| --------------------- | ---------------------------------------------------- | ------------------------------------------------ |
| `EXPO_TOKEN`          | Repository secret                                    | Authenticate EAS; never printed or committed     |
| `GITHUB_TOKEN`        | Generated by Actions (`github.token`)                | Create the Release and upload assets             |
| `EXPO_PUBLIC_API_URL` | Repository variable, default `http://localhost:3000` | Public API URL baked into the app (not a secret) |

The workflow declares `permissions: contents: write` and nothing broader. No
token value is written into the repository; only the `${{ secrets.* }}` and
`${{ github.token }}` references appear in the workflow file.

## Reproducibility

Actions are pinned to major versions, Node comes from `.nvmrc`, dependencies
are frozen to the lockfile, and the build uses the fixed `preview` profile. The
release notes record the exact source commit and CI run, so any release can be
traced back to the code that produced it.

## Device testing

CI builds and verifies the artifact but cannot test it on a physical phone.
Before a release is marked verified, a human must install the APK on a real
Android device, exercise the donor and recipient flows, and record the device
model and result in the release checklist printed in the release notes. This
manual step is the remaining acceptance item for the release.

## Demo-booth QR code

`apps/mobile/assets/install-qr.png` (and its `.svg` twin) encode
`https://github.com/dinozaoro/aahaarloop/releases/latest`, which always resolves
to the newest GitHub Release containing the APK and `INSTALL.md`. Print the PNG
at the booth: scanning it opens the latest release page on a phone, where the
APK is attached.

### Regenerating

The URL is deliberately stable, so the QR code does not change between
releases. Regenerate only if the repository moves or the install page changes:

```sh
npx --yes qrcode -t svg -o apps/mobile/assets/install-qr.svg \
  -d '#063223ff' -l '#ffffffff' -q 4 \
  'https://github.com/dinozaoro/aahaarloop/releases/latest'
npx --yes qrcode -t png -w 512 -o apps/mobile/assets/install-qr.png \
  -d '#063223ff' -l '#ffffffff' -q 4 \
  'https://github.com/dinozaoro/aahaarloop/releases/latest'
```

Check the result with any phone camera or a QR decoder before printing. The
committed PNG was decoded back to the URL above.
