# 0006 — Expo

Status: Accepted

## Context

Volunteers need a phone-first client for pickup updates, and the team cannot
maintain two native stacks. Shared matching and domain types must be reusable
without pulling web UI into the app.

## Decision

Use Expo with Expo Router in `apps/mobile`. The app consumes only
`packages/shared` and `packages/matching`, validates `EXPO_PUBLIC_API_URL` with
the shared env helpers, and will use EAS for production builds.

## Consequences

- One TypeScript codebase targets iOS and Android; EAS configuration is still
  outstanding.
- Mobile code must not import React or web components, enforced by
  `scripts/workspace.test.mjs`.
- The app currently has a shell and env config, not data screens or offline
  sync.
- Push notifications and device registration need `device_sessions` rows and
  server-side credentials before use.
